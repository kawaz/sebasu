# 作業日誌: ウェイクワード+Whisper連続記録プロトタイプ

## 日時
2025年6月25日 19:06

## 作業概要
ウェイクワードとWhisperを組み合わせて、音声入力を継続的にDuckDBに記録するプロトタイプを実装。

## 実施内容

### 1. 開発環境の準備
- サンドボックスディレクトリ `sandbox/wake-whisper-prototype/` を作成
- 開発ガイドラインに従い、メインリポジトリではなくサンドボックスで作業

### 2. アーキテクチャ設計
- マルチスレッドアーキテクチャを採用
  - メインスレッド: ウェイクワード検出
  - サブスレッド: 音声認識処理
- リングバッファで音声データを管理（ウェイクワード前の2秒間も含めて録音）

### 3. 実装したモジュール
- `config.py`: 環境変数と設定管理
- `wake_word.py`: Porcupineによるウェイクワード検出
- `audio_recorder.py`: PyAudioによる音声録音管理
- `transcriber.py`: Whisperによる音声認識
- `database.py`: DuckDBへのデータ保存
- `main.py`: メインループと状態管理

### 4. 主な機能
- ウェイクワード検出後、自動的に録音開始
- 無音検出（1.5秒）または最大30秒で録音終了
- 認識結果をDuckDBに保存
- セッション終了時に統計情報を表示

## 技術的な課題と解決

### 1. Python バージョンの互換性
- 問題: `openai-whisper`の依存関係でPython 3.11との互換性問題
- 解決: `uv pip install`を使用して直接インストール

### 2. 音声フレームサイズの調整
- Porcupineは固定フレーム長（512サンプル）を要求
- PyAudioのチャンクサイズをPorcupineの要件に合わせて設定

### 3. スレッド間の状態管理
- `is_listening`フラグで録音状態を管理
- 複数のウェイクワード検出を防ぐため、録音中は検出を無効化

## 実行方法
```bash
cd sandbox/wake-whisper-prototype
cp .env.example .env
# .envファイルにPICOVOICE_ACCESS_KEYを設定
uv sync
uv run python main.py
```

## 学んだこと
- uvによるパッケージ管理が`pip`よりも高速で依存関係の解決が優秀
- Whisperのローカル実行は初回のモデルダウンロード以外は高速
- DuckDBは軽量で組み込み用途に最適
- サンドボックスでの開発により、メインコードベースを汚さずに実験可能
